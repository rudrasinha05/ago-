# UI and UX design skills

## design.ux-flow
title: Design a user flow
roles: employee, pm
stages: discovery, architecture
keywords: ux, flow, user, journey, screens, wireframe, navigation, experience
source: AGO original (Claude, 2026-11-24)
---
1. One user, one goal per flow. 2. List the steps from entry to success; remove every step you can. 3. Show the system's response after each action. 4. Plan empty, loading, error and success states. 5. Put the main action where the eye lands; one primary button per screen. 6. Use the user's words, not internal terms. 7. Test the flow on paper with a real user before building.

## design.ui-layout
title: Clean screen layout
roles: employee
stages: architecture, implementation
keywords: ui, layout, screen, page, interface, spacing, grid, visual, design
source: AGO original (Claude, 2026-11-24)
---
1. Clear hierarchy: one headline, one primary action, then details. 2. A spacing scale (4/8/16/24/32) used everywhere. 3. Align to a grid; consistent margins. 4. Group related things; separate with space before lines. 5. At most 2 fonts and a few sizes. 6. Limit colors: neutral base, one accent, status colors. 7. Check it on a phone first; nothing overflows sideways.

## design.design-system
title: Build a design system
roles: employee, cto
stages: architecture
keywords: design, system, tokens, components, style, guide, consistency, library
source: AGO original (Claude, 2026-11-24)
---
1. Tokens first: colors, type scale, spacing, radius, shadows, as named variables. 2. Light and dark values for every color token. 3. Core components: button, input, select, card, dialog, toast, table. 4. Each component lists states: hover, focus, disabled, error, loading. 5. Accessibility built in (contrast, focus, labels). 6. Usage rules with do and don't examples. 7. One owner approves changes.

## design.mobile-ui
title: Mobile app screens
roles: employee
stages: architecture, implementation
keywords: mobile, app, phone, screen, touch, responsive, ios, android, ui
source: AGO original (Claude, 2026-11-24)
---
1. Thumb zone: main actions near the bottom. 2. Touch targets at least 44-48 pt. 3. One task per screen; short forms with the right keyboard type. 4. Readable text (16 px base) that scales with settings. 5. Show progress for anything over a second. 6. Work offline or say clearly when not. 7. Respect safe areas and both themes.

## design.copy-microcopy
title: Interface text (microcopy)
roles: employee, pm
stages: implementation
keywords: copy, microcopy, text, labels, buttons, messages, wording, ux, writing
source: AGO original (Claude, 2026-11-24)
---
1. Buttons say what happens: "Save project", not "Submit". 2. Short, plain words; one idea per sentence. 3. Errors say what went wrong and how to fix it, never blame the user. 4. Empty states explain what will appear and the first step. 5. Be consistent: one name per thing. 6. Avoid jargon and internal codes. 7. Read it aloud; cut every word that adds nothing.

## design.design-critique
title: Critique a design
roles: employee, qa, pm
stages: architecture, quality
keywords: critique, design, feedback, review, visual, mockup, improve
source: AGO original (Claude, 2026-11-24)
---
1. Restate the goal and the user first. 2. Check hierarchy: is the main thing obvious in 3 seconds? 3. Check clarity of text and actions. 4. Check consistency with the design system. 5. Check accessibility: contrast, size, labels. 6. Give feedback as problem + why + suggestion. 7. Separate must-fix from taste.
