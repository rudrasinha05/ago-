# Priority P1: the real governed task execution desk
The Company Map now surfaces its already-authenticated activity rows with exact task and linked project identity. Its actions use existing `POST /v1/console/tasks/{id}/request-approval` and `POST /v1/agents/tasks/{id}/run` endpoints, not a new privileged route. `request` requires actual task: create plus approval:request; `run` requires matching same-action approved receipt plus agent:dispatch and task:execute; internal:brief/research:brief only. Every action is rechecked and audited server side (plan, dependencies, QA, behavior, calendar and budget). A client timeout never auto-retries an uncertain result. The desk refreshes task activity, persistent notifications and approval requests after each action.

This is **explicit founder/user-directed dispatch**, not continuous background auto-employment. It avoids fake scheduled work, uncontrolled token use, GitHub changes, bypassed QA, or deployment. The separate `scripts/local_approved_agent_batch.py` remains founder-confirmed and bounded. Full project coding automation, real external GitHub credential verification, and full laptop live acceptance are separate incomplete product gates.

## Priority hardening: founder batch
The local batch script now reads actual tenant-authorized approval receipts and selects only waiting internal:brief tasks with an exact matching **approved** action. Pending/rejected/mismatched or absent receipts are not eligible even for a founder-confirmed batch. Metadata calls timeout after 15s; the single synchronous approved Ollama run receives a bounded 270s request timeout (four documented 60s role passes plus overhead). Unknown results never automatically replay and must be reconciled against durable runs and QA records. No unattended scheduling, model downloads, credential storage or GitHub mutations.
