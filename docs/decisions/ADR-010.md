# ADR-010: Auth/security

Status: selected local baseline. Adoption authority: existing reviewed repository implementation and the owner's delegated Sections 12–20 task. This record is not a fabricated independent human approval.
Date: 2026-10-10. Owner: JARVIS engineering; consequential adoption authority: founder plus a distinct authorized human reviewer.

Decision: Signed short-lived sessions, RBAC, independent approval/QA.
Source: `apps/backend/ago/auth_guard.py`.

Alternatives: Managed auth, ambient founder authority, client-only checks.
Rationale: Preserve server-derived tenant identity, encrypted MFA and safe OIDC adapters.

Performance consequence: Hashing and signature verification cost are intentional.
Operational consequence: Secret configuration, revocation epochs and tenant isolation; production vault/TLS still deferred.
Financial consequence: No required hosted identity subscription. No measured throughput or financial ROI is asserted without evidence.

Upgrade/replacement gate: Real credential/role/epoch/OIDC/AEAD tests; no child DNA can disable these controls.
Rollback: restore the prior reviewed code/manifest against a verified compatible schema and matching objects; never restore over the live database automatically.
Supersedes: none. Replacement creates a new ADR, links this ID, records compatibility, impact, baseline/candidate digests and rollback, and obtains independent exact-action architecture approval before adoption. Retain this history; do not silently rewrite the selected decision.

Evidence: linked source, architecture guards and `docs/reports/SECTIONS12_20_ACCEPTANCE.md`. References: `docs/architecture/SECTION_18_REFERENCES.md`.
