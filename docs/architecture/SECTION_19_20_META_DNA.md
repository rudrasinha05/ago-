# Sections19–20: reviewed observation and inherited organizational DNA

## MetaBrain

MetaBrain observes immutable Company Brain evidence; it does not execute decisions. An executive snapshot captures tenant tasks, independent QA, virtual credits, goals/plans, departments and workforce in one PostgreSQL statement, plus a packaged static dependency audit with policy digest. Stored scoring profile, metrics, evidence fingerprint and capture order remain the verification authority. Older snapshots lacking extended observations stay valid and are explicitly labeled needs_extended_snapshot.

GET /v1/meta/reflection reads2–100 historical sources (default20), verifies every source digest, reports organization/architecture/departments/workforce/workflows, recorded decisions, backlog/failure/approval/handoff changes, advisory proposals and independently verified evaluations. Latest100 recommendation/evaluation summaries are bounded and labeled; this is a window, not an assertion about all-time outcomes. No auto action occurs. No-history/one-source windows state insufficient_history. Counts and cumulative outcome deltas do not establish causation or AGI.

An endorsed recommendation refers to its original snapshot. POST /v1/meta/evaluations requires a later snapshot captured after endorsement and concrete actual-change evidence. Both fingerprints are verified. Before/after quality, completion and virtual-credit utilization use the same fixed baseline to avoid gaming scores by changing thresholds. Insufficient completed outcomes are explicit. Independent exact meta:evaluate:<id> approval records verified/rejected comparison; it does not prove the asserted change caused it. Human change-evidence text is a review claim, not sensor-verified execution. No external organizational action is automatic.

Self-evaluation and long-term optimization remain bounded: observe repeat risks, review historical independently assessed results and propose a human-controlled experiment. Architecture, organization, department, employee and workflow evolution routes retain ordinary approvals/permissions. General self-directed organizational redesign, causal optimization and code modification remain future sections/research.

## Organizational DNA

Full company charter: mission, vision, values, leadership_style, engineering_culture, research_culture, decision_philosophy, communication_style, innovation_philosophy, risk_appetite, documentation_philosophy, security_philosophy, hiring_philosophy, promotion_philosophy, meeting_philosophy, conflict_resolution_philosophy, learning_philosophy, quality_philosophy. Every field is nonempty bounded descriptive text. Default values are an explicit preset, not falsely attributed owner decisions.

Company versions require all18 fields. Existing clients may still submit only the three thresholds plus rationale; default full guidance is supplied. Department/employee versions may override only communication/documentation/meeting/learning philosophy, and must increase/equal quality target, decrease/equal backlog and budget-alert thresholds. These are descriptive guidance/alert controls; even company wording cannot grant execution permissions. Unknown keys, protected child keys, foreign targets, weakening and missing required company fields fail.

Effective resolution: company baseline/approved company → approved department → approved employee. Each AI runtime queries its actual tenant employee, passes resolved guidance to the allowlisted handler, and persists exact immutable DNA lineage/context with the run. Optional configured model handler receives descriptive charter while paid-model opt-in and virtual budget checks remain unchanged; no paid request is made for this batch. New employees inherit dynamically without copying stale text.

If a newly stricter parent invalidates an existing child, the child is ignored and reported parent_now_stricter; inherited parent controls remain active. Activation rechecks the current parent while holding the tenant lock, including PostgreSQL enforcement. Old version records retain history. Proposer cannot approve; pending/repeated finalization cannot activate; active versions supersede only the same scope/target.

Constitution above DNA means this subsystem cannot disable existing human authority, independent approval, tenant isolation, audit or permission checks. Fixed guards are not user-editable charter fields. This establishes the DNA boundary, not a fabricated implementation of the entire Section29 constitution or amendment process. Arbitrary descriptive text is never executed as code or an authorization rule.
